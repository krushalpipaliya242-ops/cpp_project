WHAT IT IS
  A console application (C++17) that manages a photography studio:
  customers, photographers, shoot packages and session bookings, with
  conflict detection, discounts, reports and file persistence.

FOLDER STRUCTURE
  Source/        main.cpp + all class .h/.cpp files
  Data/          customers.txt, photographers.txt, packages.txt, bookings.txt
  Diagrams/      UseCase.png, ClassDiagram.png, Sequence1.png, Sequence2.png
                 (src/ holds the scripts / .dot file used to draw them)
  Executable/    Project (Linux build).  Windows: build Project.exe (see below)
  Screenshots/   program screenshots (01..08)
  ProjectReport.pdf
  build.bat / Makefile

HOW TO BUILD
  Windows (MinGW-w64 g++ on PATH):
      build.bat                (creates Executable\Project.exe)
  Linux / macOS / MSYS2:
      make                     (creates Executable/Project)
  or by hand:
      g++ -std=c++17 -Wall -Wextra -O2 -o Executable/Project Source/*.cpp

HOW TO RUN
  Run from inside the Executable folder so that ../Data/ is found:
      cd Executable
      Project.exe              (Windows)      ./Project   (Linux)
  The program uses ../Data/ if it exists, otherwise ./Data/ (created on save).
  A different data folder can be given:  Project.exe C:\mydata

MENU
  1 Add Record        customer / photographer / package
  2 Display Records   customers, photographers, packages, bookings (with names)
  3 Search Record     by ID, name, phone, email, specialty, date, status ...
  4 Update Record     Enter keeps the old value; bookings can be rescheduled
  5 Delete Record     blocked while bookings still refer to the record
  6 Main Transaction  book a session / cancel / mark completed / view schedule
  7 Report            totals, revenue, per-photographer, package popularity
  8 Save/Load         save now, or reload from disk
  9 Exit              saves automatically, then closes

BUSINESS RULES (main transaction)
  - Studio is open 09:00-20:00 and has 2 rooms; a session may not end after 20:00.
  - A photographer cannot be booked twice at overlapping times on the same date.
  - No more than 2 sessions can overlap at once (room capacity).
  - Date must be a real calendar date (YYYY-MM-DD) and not in the past.
  - Discount: Silver 5%, Gold 10%.  Total is stored in the booking.
  - Only Confirmed bookings can be cancelled, completed or rescheduled.

VALIDATION
  Name: letters, space . ' -  (2-40)   Phone: exactly 10 digits
  Email: one @, domain with a dot      Date: valid YYYY-MM-DD
  Price > 0, hours 1-8, years 0-60, '|' is not allowed in text fields.

DATA FILE FORMAT  (text, one record per line, fields separated by '|')
  customers.txt      id|name|phone|email|membership
  photographers.txt  id|name|phone|email|specialty|experienceYears
  packages.txt       id|name|price|durationHours|numPhotos
  bookings.txt       id|customerId|photographerId|packageId|date|startHour|durationHours|totalPrice|status
  Lines starting with # are comments.  Corrupt lines are skipped with a warning.

TESTING DONE
  Scripted sessions (see ProjectReport.pdf, section 11): validation errors,
  double booking, closing time, room capacity, discount, delete protection,
  close-and-reopen persistence, corrupt data files, closed input stream.
  Built with -Wall -Wextra with zero warnings; run under AddressSanitizer +
  UndefinedBehaviorSanitizer with zero errors and zero leaks.

  own console.
